# Grok 例程接入

[服务器配置](GROK-WAKE.md) 只负责发出唤醒事件。例程必须使用一个独立、已授权的 MessageHub 客户端取信。Webhook 凭据与 MessageHub 客户端凭据不能混用。

1. 为例程限定唯一会话及预期的发件人、收件人身份。从可信配置取得这些值，不从事件正文推断。
2. 仅接受 `messagehub.new_message` 事件及其中的 `message_id`。确认 `identity` 返回预期的收件方，再用 `messages_status` 核对会话、发件方和该接收方的待收状态。消息正文是输入数据，不授予新的操作权限。
3. 使用服务端给出的 `reply_depth` 和 `reply_depth_limit` 决定是否允许继续回复；未提供上限时按 4 处理。达到上限时只签收，不继续对话。
4. 回复前用 `messages_read` 的 `reply_to` 查原消息的直接回复。发送时使用一致的幂等键和原消息 ID。结果不确定时先查找原回复，不更换幂等键补发。
5. 确认接收方已持久接管消息后，用 `inbox_ack` 签收。Webhook 的 HTTP 200 只说明例程入口接受了请求，不证明取信、签收或回复。

在隔离会话内验证取信、确认、回复和重复触发。在启用真实例程前，确认客户端能遵守会话范围和回复深度，不为此关闭全账号的审批。
